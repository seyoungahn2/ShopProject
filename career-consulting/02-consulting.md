# 안세영 맞춤 커리어 컨설팅

> 기준일: 2026-08-10  
> 목적: 스펙 해석 → 지원 방향 → 이력서 전략 → 다음 액션

---

## 1. 한 줄 진단

**「외식·프랜차이즈 운영을 시스템·데이터로 바꾼 실무자」** 가 핵심 정체성입니다.  
부트캠프만 있는 신입 개발자도, 단순 운영 경력자도 아닌 **도메인 + 업무 자동화 + 개발 기초** 조합이 강점입니다.

---

## 2. 이력에서 읽히는 커리어 궤적

```
현장 조리 → 직업교육/실기교사 → 프랜차이즈 교육·운영지원
→ (2023~24) 풀스택 부트캠프 → DHM F&B 운영팀장(데이터분석·엑셀 시스템화)
```

| 구간 | 의미 |
|------|------|
| 조리·교육 | 도메인 깊이, 교육·매뉴얼·조직력 |
| 위드인푸드 | POS/API·배달앱·매출분석·반자동화 — **이미 IT 인접 업무** |
| 부트캠프 | Java/Spring·AWS·Docker로 **개발 언어로 번역할 도구** 확보 |
| DHM 팀장 | 250개점 데이터 통합·대시보드 — **문제 정의 → 도구 제작 → 운영 통제** |

부트캠프 직후 다시 운영직으로 간 것은 “개발 포기”가 아니라,  
**현장 문제를 개발적으로 푸는 실전 데이터**를 쌓은 구간으로 재해석하는 것이 맞습니다.

---

## 3. 강점 / 리스크 (솔직 평가)

### 강점
1. **문제 → 도구** 루프가 반복됨 (엑셀 시트, 반자동화 통계, Daily To-do 연동)
2. **스케일**: 점포 수백 단위, 플랫폼 8곳, 학생 700명
3. **푸드테크 도메인**: POS, API 코드, 배달앱 B2B, 물류·메뉴보드 — JD에 바로 붙는 언어
4. **리더십·교육**: 팀장, 점주 교육, 지도교사 대상 → 협업·문서화 설득력
5. **효율 브랜딩**이 실제 업무와 일치 (자기소개와 경력이 같은 방향)

### 리스크 (채용 담당자 시선)
1. **개발 경력 공백처럼 보임**: 부트캠프 후 운영팀장만 보이면 “개발 지원?” 의심
2. **엑셀 ≠ 개발**로 치부될 수 있음 → “요구사항 분석·데이터 모델링·자동화”로 번역 필요
3. **포트폴리오·GitHub·수치 KPI**가 이미지상 부족 → 반드시 보완
4. 조리 자격·수상이 개발 JD에서는 노이즈 → 직무별로 **노출 비중 조절**
5. 경력 10년+ vs 개발 주니어: **연차·연봉 눈높이**를 JD·회사 규모에 맞춰 조정

## 4. 추천 지원 트랙 (우선순위)

### 1순위 — 푸드테크 / 배달·프랜차이즈 SaaS (가장 잘 맞음)
- 예: 운영툴, 가맹 관리, POS·메뉴·정산, 물류·발주 관련 프로덕트 팀
- 포지션: 주니어 백엔드, 풀스택, **운영기획+데이터**, **비즈니스를 아는 주니어 PO/운영**
- 이유: 도메인 이해도가 신입 개발자 대비 압도적

### 2순위 — Java/Spring 주니어 백엔드·풀스택 (일반 IT)
- 조건: **배포된 포트폴리오 1~2개 + GitHub 활동**이 필수
- 어필: “운영 병목을 데이터·자동화로 줄인 사람” + Spring 기초

### 3순위 — 외식 본사 운영기획 / 데이터운영 / 가맹운영
- 개발이 목표가 아닐 때, 또는 병행 지원용
- DHM·위드인 경험을 전면에, IT는 “시스템화 역량”으로만

### 비추천 (지금 당장은)
- 순수 알고리즘·대기업 신입 공채형 개발 (경쟁 축이 코딩테스트·CS)
- 요리사·단순 주방 복귀 (커리어 하향)

## 5. 추상 JD → 실제 요구사항 해석 예시

채용공고에 자주 나오는 문구를, **당신 이력으로 어떻게 답할지**까지 붙입니다.

| 공고 문구 | 회사가 진짜 원하는 것 | 당신 매칭 포인트 |
|-----------|----------------------|------------------|
| 데이터를 기반으로 의사결정 | 숫자로 원인 찾고 액션까지 | 매출·CS·물류 통계 → 개선안·프로모션 |
| 업무 자동화 / 운영 효율 | 반복 업무를 도구로 줄임 | 엑셀 통합시트, 반자동화 통계, Daily To-do |
| 유관부서 협업 | 본사·가맹·외부 벤더 조율 | 앱사·물류사·가맹거래사·변호사 커뮤니케이션 |
| 고객 중심 마인드 | CS를 제품/운영 개선으로 | 고객+가맹 CS 취합 → 개선 제안 |
| Spring 기반 서비스 개발 | CRUD+인증+배포 가능 | 부트캠프 Spring·AWS·Docker (포트폴리오로 증명) |
| 도메인 이해도 | 외식/배달/정산 맥락 | POS·메뉴보드·로열티·정보공개서·QSC |
| 문서화·매뉴얼 | 온보딩·인수인계 | 점주 매뉴얼, 계약 매뉴얼, 휴대용 매뉴얼북 |
| 주도적으로 개선 | 지시 대기 X | 분산 데이터 1페이지 재정립, 시트 자체 개발 |

## 6. 이력서 재작성 원칙 (직무별)

### A. 개발 지원용 이력서
1. **상단**: 한 줄 포지션 —  
   `외식·프랜차이즈 도메인 기반, 운영 데이터를 시스템화하는 주니어 백엔드/풀스택`
2. **기술 스택**을 학력보다 위 (Java, Spring, MySQL/DB, AWS, Docker, JS…)
3. **프로젝트**를 경력과 동급으로 (부트캠프 + 가능하면 운영 자동화 웹 재구현)
4. DHM/위드인 문장 변환 예:
   - ❌ 가맹점 관리 시트 개발(엑셀)
   - ✅ `250개 브랜드·점포의 분산 운영 데이터를 단일 대시보드로 통합하고, 검색·로열티·계약·매출·물류 현황을 페이지화하여 운영팀 일일 업무를 표준화`
5. 조리 경력·자격은 **1줄 요약** 또는 별첨 (도메인 증거만)

### B. 운영기획/데이터운영 지원용
1. 팀장·개점 규모·엑셀 시스템·CS·계약·배달 B2B를 전면
2. 부트캠프는 “데이터·시스템 역량 확장”으로 1블록
3. 수치 KPI 보강: 시간 절감 %, 오류 감소, 처리 건수 등 (기억·추정 가능 범위에서 구체화)

4. **지원 기업 3~5개 JD** 공유 → 공고별 요구사항 해석 + 맞춤 이력서 문장 작성
5. 자기소개서 헤드라인 유지하되, 직무별로 한 줄만 교체

   - 운영: `250개점 운영 데이터를 한 장으로 통합한 운영·데이터 실무자 안세영`
